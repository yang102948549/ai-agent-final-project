### 핵심 연출 원칙 4가지

1. **실제 캡처는 ‘풀프레임 증거 컷’, 개선 흐름은 ‘에이전트 데스크탑 대화 UI’로 분리한다.**
   - 실제 **Codex 데스크탑**과 **Paseo 3분할 멀티 에이전트 창** 캡처는 작은 썸네일로 구겨 넣지 않고, **Act 2(`P03`)에서 전용 풀프레임 컷(`1600×900`)**으로 선명하게 보여 준다.
   - 본편 **5대 개선 라운드(`P04`~`P08`)**는 Codex 데스크탑 앱을 모방한 2분할 워크스페이스 UI(왼쪽: 타이핑 대화창 · 오른쪽: `1104×690px` 단일 대형 비교 화면) 안에서 **프롬프트 입력 → 타이핑 → 전송 → 에이전트 응답 → `BEFORE → AFTER` 와이프 전환**으로 전개한다.
2. **모든 라운드는 2턴(‘1차 구현 → 2차 깎음 재요청’) 대화로 구성한다.**
   - AI가 처음 준 결과에서 멈추지 않고, 검수 후 다시 지시해 다듬어 가는 ‘깎음’ 과정을 5번 연속으로 증명한다(규정 3회 이상 초과).
3. **고해상도·가독성을 최우선으로 설계한다.**
   - `1440×900` 데스크톱 화면을 2분할로 작게 축소하지 않고, **단일 대형 화면(`1104×690px`)의 순차 와이프**를 기본으로 써서 앱 안의 글자까지 선명하게 읽히게 한다.
4. **트레일러(`video/trailer/`)와 동일한 비주얼·금지 규칙을 지킨다.**
   - 종이 바탕 `#f4f3ef`, 잉크 `#111111`, 진청록 `#176a67`/`#1f7f7c`, 글꼴 `Pretendard Variable` 하나. 보라 그라데이션·네온·이모지 카드·바운스 금지, 무음으로도 100% 이해되어야 한다.

### 2.2 라운드 1개(18초) 표준 박자표 (`P04`~`P08`)

프로토타입(16초)에서 확인된 호흡을 2초 여유 있게 다듬어, 타이핑·와이프·이유 문장을 모두 편하게 읽을 수 있도록 **18초 표준 리듬**으로 고정한다.

| 구간 | 시간 | 일어나는 일 |
|---|---|---|
| **① 문제 제시** | `0.0–0.5s` | 오른쪽 대형 화면에 `BEFORE 1` 고정. 왼쪽 하단 프롬프트 입력창 포커스 |
| **② 1차 프롬프트 타이핑** | `0.5–2.7s` | 1차 실제 요청(28~36자) 타이핑 → 전송 버튼 클릭(`#1f7f7c`) → 사용자 말풍선 등록 |
| **③ 1차 응답 & 와이프** | `2.7–7.8s` | 생각 중(`0.5s`) → 에이전트 2줄 요약 + `PASS` 칩 → **`BEFORE 1 → AFTER 1` 가로 와이프(`1.1s`)** + `BEFORE` 배지 페이드아웃 + 하단 `바꾼 이유` 등장 (3초 이상 여유 감상) |
| **④ 2차 ‘깎음’ 재요청** | `7.8–10.4s` | 2차 실제 재요청(28~36자) 타이핑 → 전송 → 2차 사용자 말풍선 + 에이전트 요약 |
| **⑤ 2차 비교 화면 전환** | `10.4–17.7s` | 오른쪽 대형 화면이 **`BEFORE 2 → AFTER 2` 와이프**(또는 모바일 대형 나란히 비교 `440×660px` / 트레일러 v1·v2 영상 비교)로 전환되어 끝까지 선명하게 유지 |
| **⑥ 전환** | `17.7–18.0s` | `0.3s` 크로스 디졸브로 다음 라운드 이동 |

### 2.3 검증 완료된 구현 규칙 (`p04-round1-branch.html` 기준선)

- **기준 코드**: [video/process/compositions/p04-round1-branch.html](process/compositions/p04-round1-branch.html) (`hyperframes check --json` 오류 0건)
- **순수 결정론 타이핑**: `gsap.timeline({ paused: true, onUpdate: syncTyping })`에서 `tl.time()`으로 문자열을 직접 슬라이스한다(`setInterval`·`tl.call` 텍스트 변경 금지).
- **한국어 어절 줄바꿈**: 모든 대화·입력·이유 텍스트에 `word-break: keep-all`을 적용한다.
- **WCAG AA 대비**: 종이 바탕(`#f4f3ef`) 위 강조 텍스트는 `#1f7f7c`(4.31:1) 대신 **`#176a67`**(4.5:1 이상)을 사용한다.
- **와이프 배지 전환**: 와이프가 완료되는 시점에 `BEFORE` 배지를 페이드아웃해 `AFTER` 화면만 깔끔하게 남긴다.

### 2.4 해상도·선명도 확보 지침 (필수 준수)

프로토타입 `ffprobe` 실측에서 `--quality draft`(`405 kbps`)와 과도한 축소(37.5% · 20%)가 화질 저하의 직접 원인으로 확인되었다. 본편 제작 시 아래 4가지를 반드시 지킨다.

| 항목 | 피해야 할 방식 | 필수 적용 지침 |
|---|---|---|
| **1. 렌더 품질** | `--quality draft` (~400 kbps, 글자 뭉개짐) | 검토용은 최소 **`--quality looks`**(CRF 16), 최종 제출본은 반드시 **`--quality delivery`** 사용. 렌더 후 `ffprobe`로 `1920×1080` · `30fps` · 고비트레이트(2,500 kbps 이상 권장) 확인 |
| **2. 앱 화면 크기** | `1440×900` 화면을 2분할(`540×338px`)로 축소 | 데스크톱 비교는 **단일 대형 화면(`1104×690px`)의 순차 와이프**를 기본으로 사용. 모바일 화면 비교 시에만 세로 대형(`440×660px`) 2장 나란히 배치 |
| **3. 작업 캡처 크기** | `1920×1080` Codex·Paseo 캡처를 `392px` 작은 썸네일로 삽입 | 작은 썸네일 삽입 폐기. 실제 Codex 데스크탑·Paseo 캡처는 **Act 2(`P03`)에서 전용 풀프레임 컷(`1600×900`)**으로 선명하게 표시 |
| **4. 원본·서체** | 1x 저해상도 캡처 + `14~18px` 얇은 컬러 글자 | `local-assets/` 고해상도 원본 PNG 우선 사용(신규 촬영 시 Playwright `deviceScaleFactor: 2`). 읽는 텍스트는 최소 **`22~26px` · 굵기 `500~600`** · 고대비 유지 |
