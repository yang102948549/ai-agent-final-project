# 만든 과정 소개 영상(작업영상) 제작 PRD 및 콘티 (`다른 곳의 하루`)

> 이 문서는 HyperFrames로 **「다른 곳의 하루」 만든 과정 소개 영상(2분 40초 MP4)**을 만들기 위한 제품 요구사항 정의서(PRD) 및 씬별 콘티다.
> 2026-11-27 2차 개편으로 **단순 스크린샷 나열 방식을 폐기**하고, **실제 Codex 데스크탑·Paseo 작업 캡처는 ‘실제 수행 증거’로 짧게 비추되, 핵심 개선 흐름 전체를 깔끔한 에이전트 데스크탑 앱 UI 안의 프롬프트 창·타이핑 대화 애니메이션 + Before/After 비교 대조**로 풀어내는 구조로 확정했다.

### 핵심 연출 원칙 4가지

1. **실제 캡처는 ‘증거 컷’, 개선의 흐름은 ‘에이전트 데스크탑 대화 UI’로 보여 준다.**
   - 실제 **Codex 데스크탑**과 **Paseo 3분할 멀티 에이전트 창** 스크린샷은 초반 작업 환경 소개(`P02`·`P03`)와 라운드 말미의 짧은 증거 컷인(1.2~1.5초)으로만 활용해 *“실제로 이렇게 작업했다”*는 신뢰를 준다.
   - 본편 6대 개선 라운드(`P04`~`P09`)는 **Codex 데스크탑 앱을 모방한 간결한 2분할 워크스페이스 UI**(왼쪽: 에이전트 대화창 · 오른쪽: Before→After 비교 미리보기) 안에서 **프롬프트 입력창 등장 → 타이핑 애니메이션 → 전송 → 에이전트 응답 → 화면 즉시 변화(Before→After)** 흐름으로 전개한다.
2. **관건은 대화창 애니메이션의 간결함과 가독성이다.**
   - 실제 앱의 자잘한 사이드바·긴 코드 출력·복잡한 메뉴는 모두 걷어내고, **프롬프트 입력창 · 사용자 말풍선 · 에이전트 2줄 요약 + `PASS` 배지**만 크게(`24–26px`) 배치해 어떤 화면 크기에서도 또렷하게 읽히게 만든다.
3. **‘깎음’의 2턴 대화를 그대로 연출한다.**
   - 한 번 시키고 끝낸 것이 아니라, 첫 결과(`AFTER 1차`)를 본 뒤 **두 번째 짧은 재요청 프롬프트가 다시 타이핑**되며 최종 결과(`AFTER 최종`)로 다듬어지는 2턴 대화 리듬을 핵심 라운드에 배치한다.
4. **트레일러(`video/trailer/`)와 동일한 비주얼·금지 규칙을 지킨다.**
   - 종이 바탕 `#f4f3ef`, 잉크 `#111111`, 포인트 `#1f7f7c`, 글꼴 `Pretendard Variable` 하나. 보라 그라데이션·네온·이모지 카드·바운스 금지, 소리를 꺼도 100% 이해되어야 한다.

### 2.2 깔끔하고 간결한 대화창 애니메이션 규격 (HyperFrames GSAP 결정론 구현)

| 요소 | 시각·모션 규격 |
|---|---|
| **창 프레임** | 흰색 `#ffffff` 카드, `1px solid #dcdad3`, 모서리 `16px`, 그림자 `0 12px 32px rgba(17,17,17,0.06)`. 상단 바 높이 `48px`(`#faf9f6`)에 최소화된 3점 아이콘과 라운드 제목만 표시 |
| **프롬프트 입력창 등장** | 하단 입력창이 아래에서 `10px` 위로 올라오며 포커스 테두리(`1.5px solid #111111`) 점등 (`0.25s`, `power2.out`) |
| **타이핑 애니메이션** | **타이머(`setInterval`) 절대 금지.** GSAP 타임라인 진행도(`0→1`)로 문자열 길이를 결정론적으로 슬라이스(`초당 20~24자`), 끝에 `2px` 깜빡이는 커서(`▍`) 배치. 실제 발화의 핵심 문장만 간결하게(28~44자) 발췌해 1.6~2.2초 안에 자연스럽게 완성 |
| **전송 → 말풍선 전환** | 입력창 우측 전송 버튼(`↑`)이 `0.12s` 눌리며 `#1f7f7c` 점등 → 입력 텍스트가 위쪽 대화 스레드의 사용자 말풍선(`#111111` 바탕 / `#ffffff` 글자, `24px 500`)으로 깔끔하게 올라감 |
| **에이전트 응답** | `0.5s` 동안 3개의 작은 점(`···`) 펄스 후, 에이전트 요약 **최대 2줄**(`22px 500`, `#222222`)과 녹색 검증 칩(`PASS`, `#1f7f7c`)이 흐림 걷히며 등장 |
| **Before → After 비교** | 두 가지 모드 중 장면에 맞는 방식 선택:<br>• **와이프 슬라이더(같은 화면 개선)**: BEFORE 위에 AFTER가 왼쪽→오른쪽(또는 중앙 와이프 바)으로 `0.9s` 동안 미끄러지며 즉각 변화 대비<br>• **좌우 분할 대조(화면 흐름·모바일 비교)**: BEFORE(좌)와 AFTER(우)를 나란히 배치하고 변경 지점에 얇은 `#1f7f7c` 강조 테두리 |
| **실제 캡처 증거 컷인** | 각 라운드 후반(또는 Act 2)에 실제 Codex 데스크탑 / Paseo 대화 스크린샷을 작은 증거 카드(`실제 작업 화면`)로 `1.5s`간 짧게 비춰 진정성을 입증 |

### 2.3 라운드 1개(16초) 표준 박자표 (`P04`~`P09`)

| 구간 | 시간 | 일어나는 일 |
|---|---|---|
| **① 문제 제시** | `0.0–0.6s` | 오른쪽 미리보기에 `BEFORE` 화면 고정. 왼쪽 대화창 하단 프롬프트 입력창 포커스 |
| **② 1차 프롬프트 타이핑** | `0.6–3.0s` | 실제 AI 요청 1차 문장이 입력창에 타이핑됨 → 전송 버튼 클릭 → 사용자 말풍선 등록 |
| **③ 에이전트 응답 & 1차 변화** | `3.0–7.5s` | 에이전트 2줄 요약 + `PASS` 칩 등장과 동시에 오른쪽 미리보기가 `BEFORE → AFTER`로 와이프/대조 전환 |
| **④ 2차 재요청(‘깎음’ 턴)** | `7.5–12.5s` | 1차 결과를 본 뒤 추가 수정 요청이 다시 타이핑 → 전송 → 오른쪽 화면이 최종 `AFTER`(또는 두 번째 비교 화면)로 정교화 |
| **⑤ 바꾼 이유 & 실제 캡처 컷인** | `12.5–15.7s` | 하단 **바꾼 이유** 띠가 고정 노출되고, 우측 하단에 실제 대화 캡처 썸네일이 `1.5s`간 증거로 등장 |
| **⑥ 전환** | `15.7–16.0s` | `0.3s` 크로스 디졸브로 다음 라운드 이동 |

## 7. 검수 기준 및 제작 순서

### 검수 기준
1. **규격**: 2분 40초(160초, 규정 2~3분), `1920×1080` MP4 정상 재생. 제작 코드 `video/process/` 커밋, 완성 MP4는 `local-assets/video/process.mp4` 보관.
2. **대화창 완성도**: 타이핑 애니메이션이 프레임 단위로 부드럽고, 말풍선(`24px`)·에이전트 요약(`22px`)·Before/After 화면이 겹치거나 잘리지 않음.
3. **평가 3요소 충족**: 고치기 전/후 비교 **6회**(규정 3회 이상), 모든 라운드에 **실제 AI 요청 원문(1·2턴)**, **실제 캡처 증거**, **수업 관점의 바꾼 이유** 포함.
4. **결함·개인정보 0건**: `hyperframes check --json` 오류 0건, 실제 학생 정보·업무 메신저·API 키 노출 0건.

### 제작 순서
1. **(완료)** 에이전트 데스크탑 대화창 UI + 타이핑 애니메이션 + Before/After 비교 콘티 확정 (이 문서).
2. **(다음)** `video/process/` HyperFrames 프로젝트 초기화 + `tools/prepare-assets.mjs`로 선별 캡처·`trailer-v1/v2` 비교 클립 준비.
3. **핵심 검증 먼저**: 공통 에이전트 대화창 컴포넌트(`p04-round1-branch.html` 1개)를 먼저 만들어 타이핑 속도·와이프 비교·가독성을 스냅숏으로 검증한 뒤 나머지 `p01`~`p11` 전개.
4. `hyperframes check --json` + 씬별 스냅숏 검수 → `local-assets/video/process.mp4` 렌더링 및 전체 재생 확인 → `REVIEW.md` 작성·커밋.
