# 트레일러 영상 제작 PRD (`다른 곳의 하루`)

> 이 문서는 HyperFrames로 **「다른 곳의 하루」 트레일러 영상(약 2분 MP4)**을 만들기 위한 제품 요구사항 정의서(PRD)다. 2026-11-27 v2를 본 뒤 콘티를 다시 짰다(v3).
>
> **v2에서 바꾼 이유**
> - 앱 화면이 흐릿했다. 1440×900 녹화를 1344×840으로 줄여 넣어 화면 속 글자가 읽히지 않았다.
> - 앱 장면이 4~8초라 화면을 살펴보려 하면 다음 장면으로 넘어갔다.
> - 두 갈래 선택에서 처음 보는 사람은 어떤 상황에서 무엇을 고르는지 알 수 없었다.
> - 결과물이 신문 기사 하나뿐이었다. 앱은 정책 제안서와 편지도 쓴다.
>
> **v3의 답**
> - 길이를 2분 이내로 늘려 앱 장면마다 8~10초를 준다.
> - 앱 녹화를 2배 해상도로 찍고, 1:1에 가까운 크기로 넣는다. 설명하는 부분은 확대해서 보여 준다.
> - 선택은 상황 한 문장 → A/B 글 → 실제 앱에서 고르는 모습 순서로 보여 준다.
> - 세 가지 글(기사·정책 제안서·편지)을 모두 보여 준다.

> **분량 주의:** 패들렛 채점 기준(`video/README.md`)은 트레일러를 **30~60초**로 적고 있다. 2026-11-27 사용자 결정으로 2분 이내로 만든다. 제출 전에 이 길이가 감점되지 않는지 확인한다. 필요하면 이 콘티에서 60초판을 따로 잘라 낸다.

## 1. 개요와 확정 결정

| 항목 | 명세 |
|---|---|
| **대상 앱** | 다른 곳의 하루 — 다른 나라 사람의 하루를 그 사람이 되어 살아 보는 웹앱 |
| **과제 평가 영역** | 트레일러 영상 15점 — *누구에게 무엇이 좋은 앱인지 전달되는지* |
| **분량·규격** | **118.5초** (`3,555 frames` @ `30fps`, 2분 이내), `1920×1080`, H.264 `yuv420p` MP4 |
| **제작 도구·위치** | HyperFrames — 프로젝트 [`video/trailer/`](trailer/), 출력 `local-assets/video/trailer-v3.mp4` |
| **인물·장면 자료** | [characters.md](../app/design/characters.md), [scenario-branches.md](../app/design/scenario-branches.md), `local-assets/video/clips/` |

### 확정 원칙

1. **사람으로 열고, 앱으로 보여 주고, 사람으로 닫는다.** 세 사람의 하루 → 앱에서 아시프의 하루를 대신 사는 흐름 → 웃는 시오네와 앱 첫 화면 순서다.
2. **앱 흐름은 실제 사용 순서를 따른다.** 사람 고르기 → 장면 읽기·AI 대화 → 선택 → 돌아보기 → 세 가지 글 → 갤러리.
3. **앱 장면은 충분히 머문다.** 앱 장면 하나는 **최소 8초**다. 장면 끝에는 화면 변화 없이 1.5초 이상 머문다. 설명하는 부분(버튼, 대화, 글)은 **확대해서** 보여 준다.
4. **선택은 세 단계로 보여 준다.** ① 상황 한 문장(글만) → ② “당신이라면 어떤 선택을 하시겠습니까?”와 A/B 선택지(글만) → ③ 실제 웹앱에서 같은 선택지를 눌러 결과로 넘어가는 모습.
5. **세 가지 글을 모두 보여 준다.** 형식 고르기 화면 다음에 신문 기사 → 정책 제안서 → 편지를 차례로 보여 준다.
6. **여는 문장과 닫는 질문은 유지한다.** “오늘, 나와 다른 하루를 사는 사람들이 있습니다.” / “내일, 우리들의 하루는 어떻게 될까요?”
7. **앱 공개 문장:** “우리는 오늘 누군가의 하루를 대신 살아 봅니다.” “중학교 도덕 수업” 같은 대상 설명 문구는 넣지 않는다.
8. **QR 코드·접속 주소·내레이션은 넣지 않는다.** 글꼴은 Pretendard 하나로 통일하고, 잔잔하고 간결하게 만든다.

## 2. 머무는 시간 규칙 (가독성)

| 규칙 | 기준 |
|---|---|
| 그림 먼저 | 컷이 바뀌면 0.4~0.5초 그림(또는 앱 화면)만 보여 준 뒤 글자를 띄운다 |
| 글자 머무는 시간 | **글자 수(띄어쓰기 포함) ÷ 8 + 1초**, 최소 2초 |
| 앱 장면 | 최소 8초. 확대가 끝난 뒤 1.5초 이상 멈춘다 |
| 한 컷 = 한 문장 | 위쪽 설명은 컷마다 한 문장(선택지 카드만 예외: 질문 + A/B) |
| 글자 자리 고정 | 인물 컷은 **왼쪽 글, 오른쪽 영상**. 앱 컷은 **위에 글, 아래에 앱 화면**. 글 카드는 **왼쪽 정렬, 세로 가운데** |
| 전환 | 0.3초 겹쳐 바꾸기만 쓴다. 빠른 컷·플래시·흔들림은 금지 |

## 3. 비주얼·모션 시스템

| 요소 | 규격 |
|---|---|
| **바탕** | 종이 `#f4f3ef`, 잉크 `#111111`, 보조 글자 `#5c5c5c`. 여는 문장과 닫는 질문만 `#111111` 암전 |
| **글꼴** | **Pretendard** 하나. 앱 장면 위쪽 문장 44px 600 / 인물 문장 50px 600 / 글 카드 본문 52px 600, 선택지 40px 500 / 여는·닫는 문장 64px 500 / 작은 정보 줄 32px 500 `#5c5c5c` |
| **인물 색** | 앱 `TONE`. 아시프 `#2d6b63`, 라마 `#3f74a8`, 암나 `#76589f`, 시오네 `#1f7f7c` |
| **앱 화면 틀** | 녹화는 **1440×900 화면을 2배 해상도(2880×1800)**로 찍는다. 영상에는 **1392×870**(실제 화면의 97%)으로 x 264, y 170에 놓아 글자가 원래 크기에 가깝게 보이게 한다. 1px `#dcdad3` 테두리, 옅은 그림자(0 12px 32px, 8%) |
| **확대(펀치인)** | 앱 틀 안의 녹화만 1.5~1.9배로 확대해 설명하는 부분을 틀 가운데로 가져온다. 0.8초 `power2.inOut`, 확대한 뒤에는 움직이지 않는다. 2배 해상도 원본이라 확대해도 선명하다 |
| **모션** | 글은 흐림이 걷히며 제자리에서 0.2초에 나타나고 움직이지 않는다. 인물 영상은 2%만 천천히 다가간다. 바운스·회전·네온·보라 그라데이션·이모지는 금지 |
| **안전 여백** | 글은 상하 80px, 좌우 110px 안 |

> S12와 S13, S13과 S14는 겹쳐 넘어간다(각 0.3초·0.5초). 시간 표의 끝값은 겹침을 포함한 값이다. 전체 길이는 118.5초다.

### S1. 여는 문장 (0–4초)

- `0.1초` “오늘,” · `0.27초` “나와 다른 하루를 사는 사람들이 있습니다.” (21자, 3.6초 머묾) · `3.85초` 글과 암전이 함께 걷힌다.

### S2. 세 사람의 하루 (4–19초, 컷마다 5초)

- 컷 안: `0–0.3초` 앞 컷과 겹쳐 영상이 들어옴 → `0.4초` 사는 곳 → `0.5초` 문장과 인물 색 띠 → `4.73초` 글이 사라짐. 문장은 4.2초 머문다(기준 4.1초).
- 4–9초 아시프 · 9–14초 라마 · 14–19초 암나

### S3. 앱 공개 (19–27초)

- 앱 틀이 0.4초에 나타나고 REC-01(캐릭터 고르기 화면)이 재생된다. 커서가 카드 위를 지나며 화면이 천천히 아래로 내려간다.
- `0.4초` 문장: **우리는 오늘 누군가의 하루를 대신 살아 봅니다.** (21자) → 끝까지 머묾(7.4초).

### S4. 한 사람 고르기 (27–35초)

- REC-02: 캐릭터 화면에서 아시프 카드를 누른다 → 인물 소개 화면(사진, 나라·사는 곳, 상황, “이 사람으로 시작”) → 커서가 “이 사람으로 시작” 위에 머문다.
- `3.5초` 인물 소개의 상황 상자와 시작 버튼 쪽으로 1.5배 확대.
- `0.4초` 문장: **한 사람을 골라, 그 사람으로 하루를 시작합니다.** (22자) → 끝까지.

### S5. 장면과 대화 (35–47초)

- REC-03: 낮 장면 「멈춰 버린 선풍기」. 본문(정전, 어머니의 숨, 쉼터 30분)이 보인다 → 답 칩 “어머니, 물 한 모금이라도 먼저 드세요.”를 누른다 → 학생 말이 오르고 어머니의 실제 AI 대답이 이어진다.
- `0.8초` 장면 본문 쪽으로 1.6배 확대 → `6초` 대화 쪽(학생 말과 AI 대답)으로 옮겨 확대.
- `0.4초` 문장: **그 사람이 겪는 장면을 읽고,** → `5.8초` **장면 속 사람들과 AI로 대화합니다.** → 끝까지.

### S6. 상황 한 문장 (47–53.5초, 글 카드)

- 종이 바탕, 왼쪽 정렬.
- `0.4초` 작은 줄: **아시프의 낮**(32px `#5c5c5c`)
- `0.5초` 본문: **정전된 찜통 집에서 어머니가 숨이 차지만, 쉼터까지는 걸어서 30분이 걸립니다.** (38자, 5.75초 → 5.8초 머묾)
- 아래에 아시프 색 띠.
- 문장은 대본(「멈춰 버린 선풍기」 본문)에 있는 사실만 쓴다.

### S7. 선택지 (53.5–61.5초, 글 카드)

- `0.4초` **당신이라면 어떤 선택을 하시겠습니까?** (52px)
- `1.2초` **A** 옆집에 어머니를 잠시 부탁한다 (40px, A는 아시프 색 네모 안 흰 글자 — 앱 버튼과 같은 모양)
- `1.8초` **B** 돈을 빌려 릭샤를 불러 쉼터로 모셔 간다
- 끝까지 머문다. 선택지는 앱 화면의 버튼 문구와 똑같이 쓴다(배포 화면에서 확인한 문구).

### S8. 웹앱에서 고르기 (61.5–71.5초)

- REC-04: 실제 선택 화면. “아시프라면, 어떻게 할까요?”와 A/B 버튼이 보인다.
- `0.8초` A/B 버튼 쪽으로 1.8배 확대 → 커서가 A 위로 와서 `4.2초`에 누른다 → 결과 화면(「이웃의 배려와 빚진 마음」, 얻은 것·잃은 것)으로 넘어간다 → `5.5초` 결과 쪽으로 옮겨 1.5배 확대.
- `0.4초` 문장: **웹앱에서는 이렇게 고릅니다.** → `5.6초` **선택에 따라 하루가 달라집니다.** → 끝까지.

### S9. 돌아보기 (71.5–79.5초)

- REC-05: 돌아보기 화면 “어려웠던 건, 선택만의 문제였을까요?” → 커서가 칸을 누르고 “어느 쪽을 골라도 바닷물이 들어오는 집은 그대로였다.”를 입력한다(시오네 예시).
- `0.8초` 질문 제목과 입력 칸 쪽으로 1.5배 확대.
- `0.4초` 문장: **무엇을 골라도 바뀌지 않은 어려움을 찾습니다.** → 끝까지.

### S10. 세 가지 글 (79.5–99.5초)

| 구간 | 화면 | 위쪽 문장 |
|---|---|---|
| 79.5–84.5 | REC-06: 글 형식 고르기(신문 기사·정책 제안서·편지)를 커서가 차례로 가리킴, 1.5배 확대 | 해결책은 세 가지 글 중 하나로 씁니다. |
| 84.5–89.5 | REC-07: 완성된 **신문 기사**(시오네)를 천천히 내려 봄 | 신문 기사로 알리고, |
| 89.5–94.5 | REC-08: 완성된 **정책 제안서**(마리암)를 천천히 내려 봄 | 정책 제안서로 바꿀 길을 내고, |
| 94.5–99.5 | REC-09: 완성된 **편지**(코피)를 천천히 내려 봄 | 편지로 마음을 전합니다. |

- 세 문장은 이어 읽으면 한 문장이 된다. 각 글 화면은 문서 제목과 첫 단락이 틀 가운데 오도록 1.3배 확대한 상태로 시작한다.

### S11. 갤러리 (99.5–107.5초)

- REC-10: 결과물 갤러리(기사·편지·정책 제안서 카드, 하트) → 커서가 카드 하나를 눌러 크게 보기가 열린다.
- `0.4초` 문장: **완성한 글은 학급 갤러리에서 함께 읽습니다.** → 끝까지.

### S12. 시오네 (107.5–111.8초)

- 인물 컷 배치. 시오네 클립의 끝 4.3초를 써서 웃는 얼굴로 끝난다. `0.4초` 정보 줄 **투발루 바이투푸섬 · 시오네, 13살**, `3.4초`에 글이 빠진다.

### S13. 앱 첫 화면 (111.5–115.5초, 앞뒤 겹침 포함)

- REC-11: 앱 첫 화면(「다른 곳의 하루」 제목, 12명 앨범이 흐름, 커서 없음). 시오네 위로 0.3초 겹쳐 들어온다. 앨범 속 시오네 카드로 이어진다.

### S14. 닫는 질문 (115–118.5초)

- `0–0.33초` 앱 첫 화면 위로 암전 → `0.33초` “내일,” · `0.53초` “우리들의 하루는 어떻게 될까요?” → 끝까지 정지(3.0초).

### 글 다듬기 기준

- 화면의 모든 문장은 소리 내어 읽어 자연스러운 한국어여야 한다. 번역투나 어색한 선언문은 쓰지 않는다.
- 물음표는 선택지 질문(S7)과 닫는 질문(S14) 두 곳에만 쓴다.
- 상황 문장과 선택지는 앱 대본·배포 화면 문구 그대로의 사실만 쓴다.

### 7.1 인물 영상 (`local-assets/video/clips/`, Veo 3.1 Fast, 8초·720×1280)

### 7.2 앱 화면 녹화 (REC-01~11)

배포 사이트(`https://onischool.net/anotherday/`)를 `video/trailer/tools/record-app.mjs`(Playwright + Chrome 화면 전송)로 조작하며 녹화한다.
- **해상도:** 화면 1440×900, **deviceScaleFactor 2 → 2880×1800 프레임**. MP4는 2880×1800, CRF 16 이하로 만든다.
- **위치:** 원본은 `local-assets/video/app-recordings/`, 쓰는 파일은 `video/trailer/assets/app/`(Git 제외).
- **길이:** 장면 길이보다 2초 이상 길게 녹화한다. 끝에 2초 이상 정지 구간을 둔다.

| 녹화 | 쓰는 곳 | 화면과 동작 | 데이터 |
|---|---|---|---|
| REC-01 | S3 | 캐릭터 고르기 화면을 천천히 훑음 | 실제 화면 |
| REC-02 | S4 | 아시프 카드 클릭 → 인물 소개 → “이 사람으로 시작”에 커서 | 실제 화면 |
| REC-03 | S5 | 아시프 낮 장면 → 답 칩 클릭 → 어머니의 AI 대답(기다리는 시간은 녹화에서 뺌) | **실제 배포 AI** |
| REC-04 | S8 | 아시프 낮 선택 화면 → A 클릭 → 결과 | AI 미연결 상태 화면(선택지가 바로 보임) |
| REC-05 | S9 | 시오네 돌아보기에 바뀌지 않은 어려움 입력 | 예시 작성 |
| REC-06 | S10 | 글 형식 고르기(기사·정책 제안서·편지) | 예시 상태 |
| REC-07 | S10 | 신문 기사 완성 화면(시오네) | 예시 작성본(`app/tools/capture-docs.mjs`와 같은 글) |
| REC-08 | S10 | 정책 제안서 완성 화면(마리암) | 예시 작성본(`app/tools/gallery-mock.mjs` 글) |
| REC-09 | S10 | 편지 완성 화면(코피) | 예시 작성본(`app/tools/gallery-mock.mjs` 글) |
| REC-10 | S11 | 갤러리 → 카드 하나 크게 보기 | **예시 데이터(`gallery-mock.mjs`)로 가로챔.** 실제 학생 글이 찍히지 않음 |
| REC-11 | S13 | 앱 첫 화면, 12명 앨범이 흐름(커서 없음) | 실제 화면 |

- **개인정보:** 실제 학생 정보, API 키, 교사 비밀번호가 화면에 나오지 않게 한다. 예시 이름은 가린 형태(`김*늘`)만 쓴다.
- **문구 대조:** S7 선택지 문구는 REC-04 화면의 버튼 문구와 똑같아야 한다. 녹화 후 대조한다.

## 9. 검수 기준

1. **규격**: 2분 이내(118.5초), `1920×1080` MP4가 정상 재생된다.
2. **처음 보는 사람 기준**: 소리를 끄고 한 번 본 사람이 다음 네 가지를 말할 수 있다.
   - ① 다른 나라 사람의 하루를 그 사람이 되어 살아 보는 앱이다.
   - ② 어떤 상황에서 무엇을 고르는지, 앱에서 어떻게 고르는지 안다.
   - ③ 대화하고, 돌아보고, 기사·정책 제안서·편지 중 하나를 쓰고, 갤러리에서 나눈다.
   - ④ 앱 이름은 「다른 곳의 하루」다.
3. **앱 화면 선명도**: 렌더한 MP4에서 확대 구간의 앱 글자(본문·버튼·대화)가 읽힌다. 확대하지 않은 구간도 버튼과 제목은 읽힌다.
4. **속도**: 앱 장면은 8초 이상이고, 확대가 끝난 뒤 1.5초 이상 멈춘다. 처음부터 끝까지 재생해 "보려는데 넘어가는" 장면이 없다.
5. **결함 0건**: 글자 잘림·겹침·안전 여백 침범이 없다. AI 기본 디자인 요소가 없다.
6. **안전**: 실제 학생 정보·API 키가 보이지 않는다. 음원 출처를 기록한다.

## 10. 제작 순서

1. **(완료)** 콘티 v3(이 문서).
2. **(다음)** `record-app.mjs`를 2배 해상도와 REC-01~11로 고쳐 녹화하고, 하나씩 열어 확인한다(선명도, 동작, 개인정보, S7 문구 대조).
3. 인물 클립을 5.3초로 다시 자르고, `build-scenes.mjs`에 장면 14개와 확대 위치를 넣어 만든다.
4. `hyperframes check`와 스냅숏으로 검토하고(특히 확대 구간 선명도) `local-assets/video/trailer-v3.mp4`로 렌더링한다. 처음부터 끝까지 재생해 확인한다.
5. 음원이 정해지면 배경 음악과 클릭 소리를 넣는다. 제출 길이 기준(30~60초)을 다시 확인한다.
