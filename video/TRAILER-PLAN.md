# 트레일러 영상 제작 PRD (`다른 곳의 하루`)

> 이 문서는 HyperFrames로 **「다른 곳의 하루」 트레일러 영상(약 2분 MP4)**을 만들기 위한 제품 요구사항 정의서(PRD)다. 2026-11-27 콘티 v3를 고쳐 v3.1로 정리했다.
>
> **v2에서 바꾼 이유:** 앱 화면이 흐리고(1440×900 녹화를 줄여 넣음), 앱 장면이 짧아 살펴볼 수 없었다. 선택 장면은 상황을 알 수 없었고, 결과물은 신문 기사 하나뿐이었다.
>
> **v3에서 다시 고친 것(v3.1)**
> - 12명은 앱 화면 캡처 대신 **사진 썸네일**로 보여 주고, 사람마다 나라와 상황을 짧게 붙인다.
> - 닫는 질문은 검은 화면이 아니라 **웃는 시오네 얼굴과 함께** 띄운다.
> - 그다음 **12명 썸네일 → 「다른 곳의 하루」 타이틀 → 페이드아웃**으로 끝낸다.

> **분량 주의:** 패들렛 채점 기준(`video/README.md`)은 트레일러를 **30~60초**로 적고 있다. 2026-11-27 사용자 결정으로 2분 이내로 만든다. 제출 전에 이 길이가 감점되지 않는지 확인하고, 필요하면 60초판을 따로 잘라 낸다.

## 1. 개요와 확정 결정

| 항목 | 명세 |
|---|---|
| **대상 앱** | 다른 곳의 하루 — 다른 나라 사람의 하루를 그 사람이 되어 살아 보는 웹앱 |
| **과제 평가 영역** | 트레일러 영상 15점 — *누구에게 무엇이 좋은 앱인지 전달되는지* |
| **분량·규격** | **119.4초** (`3,582 frames` @ `30fps`, 2분 이내), `1920×1080`, H.264 `yuv420p` MP4 |
| **제작 도구·위치** | HyperFrames — 프로젝트 [`video/trailer/`](trailer/), 출력 `local-assets/video/trailer-v3.mp4` |
| **인물·장면 자료** | [characters.md](../app/design/characters.md), [scenario-branches.md](../app/design/scenario-branches.md), `local-assets/photoreal-characters/`, `local-assets/video/clips/` |

### 확정 원칙

1. **사람으로 열고, 앱으로 보여 주고, 사람으로 닫는다.**
   - 처음: 여는 문장 → 세 사람의 하루 → 12명 썸네일(나라·상황)
   - 가운데: 앱에서 아시프의 하루를 대신 사는 흐름
   - 끝: 웃는 시오네와 닫는 질문 → 12명 썸네일과 타이틀 → 페이드아웃
2. **12명은 사진 썸네일로 보여 준다.** 앱 화면 캡처를 쓰지 않는다. 썸네일마다 이름 · 나라 · 상황 한 줄(앱 속 인물별 이야기 제목)을 붙인다.
3. **앱 흐름은 실제 사용 순서를 따른다.** 사람 고르기 → 장면 읽기·AI 대화 → 선택 → 돌아보기 → 세 가지 글 → 갤러리.
4. **앱 장면은 충분히 머문다.** 최소 8초. 확대가 끝난 뒤 1.5초 이상 멈춘다. 설명하는 부분(버튼, 대화, 글)은 확대해서 보여 준다.
5. **선택은 세 단계로 보여 준다.** ① 상황 한 문장(글만) → ② “당신이라면 어떤 선택을 하시겠습니까?”와 A/B 선택지(글만) → ③ 실제 웹앱에서 같은 선택지를 눌러 결과로 넘어가는 모습.
6. **세 가지 글을 모두 보여 준다.** 형식 고르기 → 신문 기사 → 정책 제안서 → 편지.
7. **문장:** 여는 문장 “오늘, 나와 다른 하루를 사는 사람들이 있습니다.”(검은 화면) / 앱 공개 “우리는 오늘 누군가의 하루를 대신 살아 봅니다.” / 닫는 질문 “내일, 우리들의 하루는 어떻게 될까요?”(웃는 시오네와 함께). “중학교 도덕 수업” 같은 대상 설명 문구는 넣지 않는다.
8. **QR 코드·접속 주소·내레이션은 넣지 않는다.** 글꼴은 Pretendard 하나로 통일하고, 잔잔하고 간결하게 만든다.

## 2. 머무는 시간 규칙 (가독성)

| 규칙 | 기준 |
|---|---|
| 그림 먼저 | 컷이 바뀌면 0.4~0.5초 그림(또는 앱 화면)만 보여 준 뒤 글자를 띄운다 |
| 글자 머무는 시간 | **글자 수(띄어쓰기 포함) ÷ 8 + 1초**, 최소 2초 |
| 앱 장면 | 최소 8초. 확대가 끝난 뒤 1.5초 이상 멈춘다 |
| 썸네일 장면 | 12명이 다 놓인 뒤 7초 이상 머물러 이름·나라·상황을 훑어볼 수 있게 한다 |
| 한 컷 = 한 문장 | 위쪽 설명은 컷마다 한 문장(선택지 카드만 예외: 질문 + A/B) |
| 글자 자리 고정 | 인물 컷은 **왼쪽 글, 오른쪽 영상**. 앱 컷은 **위에 글, 아래에 앱 화면**. 글 카드는 **왼쪽 정렬, 세로 가운데** |
| 전환 | 0.3초 겹쳐 바꾸기만 쓴다. 마지막만 1.1초 페이드아웃. 빠른 컷·플래시·흔들림은 금지 |

### S1. 여는 문장 (0–4초)

- 검은 화면. `0.1초` “오늘,” · `0.27초` “나와 다른 하루를 사는 사람들이 있습니다.” (21자, 3.6초 머묾) · `3.85초` 글과 검은 화면이 함께 걷힌다.

### S2. 세 사람의 하루 (4–18.4초, 컷마다 4.8초)

- 컷 안: `0–0.3초` 앞 컷과 겹쳐 영상이 들어옴 → `0.4초` 사는 곳 → `0.5초` 문장과 인물 색 띠 → `4.53초` 글이 사라짐. 문장은 4.0초 머문다(기준 4.1초에 가까움).
- 4–8.8초 아시프 · 8.8–13.6초 라마 · 13.6–18.4초 암나

### S3. 12명 썸네일 (18.4–28.4초)

## 9. 검수 기준

1. **규격**: 2분 이내(119.4초), `1920×1080` MP4가 정상 재생된다. 마지막 프레임은 검은 화면이다.
2. **처음 보는 사람 기준**: 소리를 끄고 한 번 본 사람이 다음 네 가지를 말할 수 있다.
   - ① 다른 나라 사람의 하루를 그 사람이 되어 살아 보는 앱이다(12명이 누구이고 어디에 사는지 대략 안다).
   - ② 어떤 상황에서 무엇을 고르는지, 앱에서 어떻게 고르는지 안다.
   - ③ 대화하고, 돌아보고, 기사·정책 제안서·편지 중 하나를 쓰고, 갤러리에서 나눈다.
   - ④ 앱 이름은 「다른 곳의 하루」다.
3. **선명도**: 썸네일의 이름·나라·상황과 확대 구간의 앱 글자가 렌더한 MP4에서 읽힌다.
4. **속도**: 앱 장면은 8초 이상, 썸네일 장면은 다 놓인 뒤 7초 이상 머문다. 처음부터 끝까지 재생해 "보려는데 넘어가는" 장면이 없다.
5. **결함 0건**: 글자 잘림·겹침·안전 여백 침범이 없다. AI 기본 디자인 요소가 없다.
6. **안전**: 실제 학생 정보·API 키가 보이지 않는다. 음원 출처를 기록한다.

## 10. 제작 순서

1. **(완료)** 콘티 v3.1(이 문서).
2. **(다음)** `record-app.mjs`를 2배 해상도와 REC-01~09로 고쳐 녹화하고, 하나씩 열어 확인한다(선명도, 동작, 개인정보, 문구 대조).
3. `prepare-assets.sh`에 썸네일 12장과 시오네 끝 프레임을 더하고, 인물 클립을 5.1초로 다시 자른다. `build-scenes.mjs`에 장면 13개와 확대 위치를 넣어 만든다.
4. `hyperframes check`와 스냅숏으로 검토하고(썸네일 글자, 확대 구간 선명도) `local-assets/video/trailer-v3.mp4`로 렌더링한다. 처음부터 끝까지 재생해 확인한다.
5. 음원이 정해지면 배경 음악과 클릭 소리를 넣는다. 제출 길이 기준(30~60초)을 다시 확인한다.
