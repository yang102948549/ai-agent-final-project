# 트레일러 영상 제작 PRD (`다른 곳의 하루`)

> 이 문서는 HyperFrames로 **「다른 곳의 하루」 트레일러 영상(59.5초 MP4)**을 만들기 위한 제품 요구사항 정의서(PRD)다. 2026-11-27 초안 v1을 본 뒤 콘티를 다시 짰다.
>
> **v1에서 바꾼 이유:** v1은 12명의 이름과 장면 제목만 3.5초씩 이어 붙였다. 처음 보는 사람은 그 사람이 누구이고 무슨 상황인지 알 수 없었다. 앱 화면이 하나도 없어 이것이 앱이라는 것도 전달되지 않았다. 새 콘티는 **세 사람의 하루를 한 문장씩 설명하고, 실제 앱을 쓰는 장면으로 수업 흐름을 보여 준다.**

## 1. 개요와 확정 결정

| 항목 | 명세 |
|---|---|
| **대상 앱** | 다른 곳의 하루 — 다른 나라 사람의 하루를 그 사람이 되어 살아 보는 웹앱 |
| **과제 평가 영역** | 트레일러 영상 15점 — *누구에게 무엇이 좋은 앱인지 1분 안에 전달되는지* |
| **분량·규격** | **59.5초** (`1,785 frames` @ `30fps`), `1920×1080`, H.264 `yuv420p` MP4 |
| **제작 도구·위치** | HyperFrames — 프로젝트 [`video/trailer/`](trailer/), 출력 `local-assets/video/trailer-v2.mp4` |
| **인물·장면 자료** | [characters.md](../app/design/characters.md), [scenario-branches.md](../app/design/scenario-branches.md), `local-assets/video/clips/` |

### 확정 원칙

1. **사람으로 열고, 앱으로 보여 주고, 사람으로 닫는다.** 세 사람의 하루 → 앱에서 그 하루를 대신 사는 장면 → 웃는 시오네와 앱 첫 화면 순서다.
2. **인물은 "누가, 어디서, 무엇을 하는지" 한 문장으로 소개한다.** 앱 대본의 장면 제목을 그대로 띄우지 않는다. 12명을 하나씩 소개하지 않는다. 12명은 앱의 캐릭터 고르기 화면과 첫 화면 사진 흐름으로 한 번에 보인다.
3. **앱 이용 장면이 영상의 가운데를 차지한다.** 배포 사이트를 실제로 조작하며 녹화한 화면으로 고르기 → AI 대화 → 돌아보기·글쓰기 → 갤러리를 보여 준다. 장면마다 무엇을 하는지 한 줄을 붙인다.
4. **시오네는 마지막에 둔다.** 시오네 클립은 웃는 얼굴로 끝나므로 영상의 끝 인물로 쓰고, 앱 첫 화면으로 이어 붙인다.
5. **여는 문장과 닫는 질문은 유지한다.** “오늘, 나와 다른 하루를 사는 사람들이 있습니다.”로 열고 “내일, 우리들의 하루는 어떻게 될까요?”로 닫는다.
6. **"중학교 도덕 수업" 같은 대상 설명 문구는 넣지 않는다.** 앱 공개는 “우리는 오늘 누군가의 하루를 대신 살아 봅니다.”로 한다.
7. **QR 코드·접속 주소·내레이션은 넣지 않는다.** 소리를 꺼도 화면 글만으로 이해되어야 한다.
8. **글꼴은 Pretendard 하나로 통일하고, 잔잔하고 간결하게 만든다.**

## 2. 머무는 시간 규칙 (가독성)

| 규칙 | 기준 |
|---|---|
| 그림 먼저 | 컷이 바뀌면 **0.4~0.5초** 그림(또는 앱 화면)만 보여 준 뒤 글자를 띄운다 |
| 글자 머무는 시간 | **글자 수(띄어쓰기 포함) ÷ 8 + 1초**, 최소 **2초** |
| 한 컷 = 한 문장 | 화면 글은 컷마다 한 문장. 최대 2줄, 줄당 22자 이내 |
| 글자 자리 고정 | 인물 컷은 늘 **왼쪽에 글, 오른쪽에 영상**. 앱 컷은 늘 **위에 글, 아래에 앱 화면** |
| 전환 | 0.3초 겹쳐 바꾸기만 쓴다. 빠른 컷·플래시·흔들림은 금지 |
| 핵심 문장 뒤 정지 | 여는 문장, 앱 공개 문장, 가운데 질문, 닫는 질문은 다 뜬 뒤 **2초 이상** 멈춘다 |

## 3. 비주얼·모션 시스템

| 요소 | 규격 |
|---|---|
| **바탕** | 종이 `#f4f3ef`, 잉크 `#111111`, 보조 글자 `#5c5c5c`. 여는 문장과 닫는 질문만 `#111111` 암전 바탕 |
| **글꼴** | **Pretendard**(가변 글꼴, `video/trailer/assets/fonts/PretendardVariable.woff2`) 하나. 인물·앱 문장 44–56px 600, 여는 문장·닫는 질문 64px 500, 작은 정보 줄 32px 500 `#5c5c5c` |
| **인물 색** | 앱 `TONE`과 같다. 아시프 `#2d6b63`, 라마 `#3f74a8`, 암나 `#76589f`, 시오네 `#1f7f7c`. 문장 아래 72×5px 띠에만 쓴다 |
| **앱 화면 틀** | 1440×900 녹화를 **1344×840**으로 줄여 가로 가운데(x 288), 세로 y 180에 놓는다. 1px `#dcdad3` 테두리와 아주 옅은 그림자(0 12px 32px, 8%)만 쓴다. 기기 목업(노트북 그림)은 쓰지 않는다 |
| **모션** | 글은 흐림이 걷히며 제자리에서 0.2초 만에 나타나고, 나타난 뒤에는 움직이지 않는다. 인물 영상은 2%만 천천히 다가간다. 앱 화면은 녹화 속 커서와 화면 변화가 움직임을 맡고, 틀 자체는 움직이지 않는다. 바운스·회전·네온·보라 그라데이션·이모지·가운데 정렬 일색은 금지 |
| **안전 여백** | 글은 상하 108px, 좌우 110px 안(제목 안전 영역) |

### 한눈에 보기

**흐름**
- 처음 보는 사람이 따라가는 순서는 이렇다: 다른 하루를 사는 사람들이 있다 → (세 사람의 하루) → 우리가 그 하루를 대신 살아 본다 → 고르고, 대화하고, 쓰고, 나눈다 → (그 하루 끝에 웃는 시오네) → 이 앱의 이름 → 내일 우리의 하루는?
- S8→S9는 시오네의 웃는 얼굴에서 앱 첫 화면으로 0.3초 겹쳐 넘어간다. 첫 화면 사진 흐름 속에 시오네 카드가 있어 같은 사람이 이어진다.

### S1. 여는 문장 (`0–120f`)

- `0–3f` 암전. `3f` “오늘,” · `8f` “나와 다른 하루를 사는 사람들이 있습니다.” (21자) → `8–116f` 머묾(3.6초). 흐림이 걷히며 나타남, 64px 500.
- `116–120f` 글과 암전이 함께 걷히고, 아시프 컷이 0.3초 겹쳐 들어온다.

### S2. 세 사람의 하루 (`120–534f`, 컷마다 138f = 4.6초)

| 컷 안 시간 | 일어나는 일 |
|---|---|
| `0–9f` | 앞 컷과 0.3초 겹쳐 영상이 들어온다 |
| `12f` | 작은 정보 줄(사는 곳)이 나타난다 |
| `15f` | 문장(48px 600, 최대 2줄)이 나타나고, 아래에 인물 색 띠가 펼쳐진다 |
| `15–130f` | 그대로 머문다(문장 3.8초, 기준 4.1초에 가까움 — 렌더 후 체감 확인) |
| `130–138f` | 글이 사라지고 다음 컷으로 넘어간다 |

- `120–258f` 아시프 · `258–396f` 라마 · `396–534f` 암나

### S3. 앱 공개 (`534–708f`)

- `534–546f` 종이 바탕 위로 앱 화면 틀이 0.4초에 걸쳐 나타난다. 녹화 REC-01(캐릭터 고르기 화면, 12명 카드가 보이고 천천히 아래로 훑음)이 재생된다.
- `546f` 위쪽에 문장: **우리는 오늘 누군가의 하루를 대신 살아 봅니다.** (21자, 3.6초 → 5.4초 머묾)
- 이 문장이 앱이라는 것과 앱의 핵심 경험을 함께 알린다.

### S4. 고르기 (`708–942f`)

- REC-02: 아시프 낮 장면 「멈춰 버린 선풍기」(사진, 이야기, 어머니 대사, A/B 선택 버튼이 한 화면에 보임).
- `720f` 위쪽 문장: **당신이라면 어떤 선택을 하시겠습니까?** (17자, 3.1초) → `720–822f` 머묾.
- `822f` 녹화 속 커서가 버튼 하나를 누르고 결과 화면으로 넘어간다.
- `834f` 위쪽 문장이 **선택에 따라 하루가 달라집니다.** (14자, 2.75초)로 바뀌어 `834–942f` 머문다.

### S5. AI 대화 (`942–1128f`)

- REC-03: 장면 속 사람과 대화하는 화면. 답 칩을 누르면 학생 말이 올라가고 인물의 대답이 이어진다.
- `954f` 위쪽 문장: **장면 속 사람들과 AI로 대화합니다.** (15자, 2.9초) → 끝까지 머문다.

### S6. 돌아보고 쓰기 (`1128–1332f`)

- REC-04: 돌아보기 화면에서 문장 틀을 눌러 20자 이상 채움 → 신문 기사 결과물 화면으로 넘어감.
- `1140f` 위쪽 문장: **바뀌지 않는 어려움을 찾고, 해결책을 씁니다.** (21자, 3.6초) → 끝까지 머문다(6.4초).

### S7. 갤러리 (`1332–1458f`)

- REC-05: 결과물 갤러리(기사·정책 제안서·편지 카드, 하트).
- `1344f` 위쪽 문장: **친구들의 글을 함께 읽습니다.** (13자, 2.6초) → 끝까지 머문다(3.8초).

### S8. 시오네 (`1458–1578f`)

- 인물 컷 배치. `clips/04-tuvalu.mp4`의 **마지막 4.3초**를 써서 웃는 얼굴로 끝나게 한다.
- `1470f` 작은 정보 줄만: **투발루 바이투푸섬 · 시오네, 13살**. 문장은 넣지 않는다(웃음이 말을 대신한다).

### S9. 앱 첫 화면 (`1578–1680f`)

- `1569–1578f` 시오네 영상에서 앱 첫 화면 틀로 0.3초 겹쳐 넘어간다.
- REC-06: 앱 첫 화면. 「다른 곳의 하루」 제목, “같은 하늘 아래, 전혀 다른 하루.” 소개 글, 12명 사진이 가로로 흐르는 앨범.
- 위쪽 문장은 띄우지 않는다. 앱 화면 속 제목이 영상의 제목이다.

### S10. 닫는 질문 (`1680–1785f`)

- `1680–1690f` 종이 바탕이 암전으로 바뀐다. `1690f` “내일,” · `1696f` “우리들의 하루는 어떻게 될까요?” (16자) → `1696–1785f` 끝까지 정지(3.0초).
- 배경 음악은 `1690f`부터 사그라들어 마지막 프레임에서 멈춘다.

### 글 다듬기 기준

- 화면의 모든 문장은 소리 내어 읽어 자연스러운 한국어여야 한다. 번역투나 어색한 선언문은 쓰지 않는다.
- 물음표는 가운데 질문(S4)과 닫는 질문(S10) 두 곳에만 쓴다.

## 9. 검수 기준

1. **규격**: 59.5초, `1920×1080` MP4가 정상 재생된다.
2. **처음 보는 사람 기준**: 소리를 끄고 한 번 본 사람이 다음 세 가지를 말할 수 있다. ① 다른 나라 사람의 하루를 그 사람이 되어 살아 보는 앱이다. ② 고르고, AI와 대화하고, 글을 쓰고, 나눈다. ③ 앱 이름은 「다른 곳의 하루」다.
3. **속도**: 모든 문장이 2절 규칙만큼 머물고, 실제 MP4를 처음부터 끝까지 재생해 읽기 버거운 컷이 없다.
4. **앱 화면**: 앱 화면은 실제 배포 사이트를 녹화한 것이다. 글자가 1344×840 틀 안에서 읽힐 만큼 선명하다.
5. **존엄**: 인물 문장은 어려움만 늘어놓지 않고 행동을 담담하게 쓴다. 마지막 인물은 웃는 시오네다.
6. **결함 0건**: 글자 잘림·겹침·제목 안전 영역 침범이 없다. AI 기본 디자인 요소가 없다.
7. **안전**: 실제 학생 정보, API 키, 교사 비밀번호가 녹화에 보이지 않는다. 음원 출처를 기록한다.
