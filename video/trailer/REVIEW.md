# 트레일러 v2 검토 (2026-11-27)

콘티: [../TRAILER-PLAN.md](../TRAILER-PLAN.md) v2(커밋 `fcca3d2`).
출력: `local-assets/video/trailer-v2.mp4` — 1920×1080, 30fps, H.264 yuv420p, 59.5초, 25.5MB, 무음.
v1(`local-assets/video/trailer-v1.mp4`, 12명 장면 제목 나열)은 과정 소개 영상의 "고치기 전" 자료로 남겼다.

## 만든 방식

- **장면 10개** (`compositions/`)
  - 직접 쓴 파일: opening, closing
  - `tools/build-scenes.mjs`가 콘티 데이터로 만드는 파일: people, app-reveal, app-choice, app-chat, app-write, app-gallery, sione, app-home
- **글꼴과 움직임:** 글꼴은 Pretendard 하나다. 글은 흐림이 걷히며 0.2초 만에 나타난 뒤 움직이지 않는다. 인물 영상은 2%만 천천히 다가간다. 앱 화면은 틀이 고정되어 있고, 녹화 속 커서와 화면 변화가 움직임을 맡는다.
- **앱 녹화** (`tools/record-app.mjs`)
  - 배포 사이트를 Playwright(설치된 Chrome)로 조작하며 Chrome 화면 전송(CDP screencast)으로 1440×900 JPEG 프레임을 받고, ffmpeg로 30fps MP4를 만든다.
  - 커서는 페이지에 그려 넣고, 사람 손처럼 천천히 움직인다.
  - AI 응답을 기다리는 약 10초는 녹화를 멈춰 뺐다.
- **녹화별 내용**

| 녹화 | 내용 | 데이터 |
|---|---|---|
| REC-01 | 캐릭터 고르기(열두 명의 하루)를 천천히 훑음 | 실제 화면 |
| REC-02 | 아시프 낮 「멈춰 버린 선풍기」에서 A를 누르면 결과 화면 | AI 미연결 상태로 선택지가 바로 보이는 실제 화면 |
| REC-03 | 답 칩을 누르면 어머니의 **실제 AI 대답**이 이어짐 | 배포 AI. 대답 “아시프야, 너 일하러 가야지…”가 장면에 맞는 것을 확인 |
| REC-04a / 04b | 시오네 돌아보기에 “어느 쪽을 골라도 바닷물이 들어오는 집은 그대로였다.”를 입력 / 신문 기사 결과물 | 예시 작성본(`app/tools/capture-docs.mjs`와 같은 글) |
| REC-05 | 결과물 갤러리에서 하트를 누름 | **앱의 예시 데이터(`app/tools/gallery-mock.mjs`)로 가로채** 실제 학생 글이 찍히지 않음 |
| REC-06 | 앱 첫 화면, 12명 앨범이 흐름(커서 없음) | 실제 화면 |

- **시오네 → 앱 첫 화면:** 웃는 얼굴로 끝나는 시오네 클립 위로 앱 첫 화면이 0.3초 겹쳐 들어온다. 앨범 가운데에 시오네 카드가 있어 같은 사람이 이어진다.

## 측정한 것

- **`hyperframes check`:** 오류 0건. 남은 경고는 두 가지다.
  - `first_frame_empty`: 0초가 암전이다. 의도한 시작이다.
  - `film_silent`: 음원이 아직 없다.
- **여는 문장과 닫는 질문의 긴 정지:** `data-hold`로 의도한 정지라고 표시했다.
- **렌더 결과 확인**
  - 규격은 ffprobe로 확인했다.
  - 프레임 8장을 MP4에서 뽑아 직접 봤다. 고르기의 클릭 → 결과, 대화의 칩 → AI 대답, 기사, 갤러리가 모두 담겼다.
  - 앱 틀 안의 변화량을 쟀다. 고르기 장면은 800→850프레임 사이 10.35, 대화 장면은 990→1020프레임 사이 2.93이었다. 갤러리는 하트만 바뀌어 0.05였다.
- **고친 것:** 시오네 글이 앱 첫 화면 겹침 구간(52.3초)까지 남아 겹쳐 보였다. 글이 빠지는 시점을 3.4초로 앞당겨 겹침 전에 사라지게 했다.

## 눈으로만 본 것과 아직 확인하지 않은 것

- 처음부터 끝까지 실시간으로 재생한 체감 속도는 사용자 확인이 필요하다. 특히 세 사람 문장(3.8초)과 갤러리(4.2초)가 짧게 느껴지는지 봐야 한다.
- 앱 화면은 1440×900을 1344×840으로 줄였다. 앱 본문 글자(약 13px)는 영상에서 읽히기보다 "화면이 어떻게 생겼는지" 보이는 정도다. 핵심은 위쪽 문장이 전달한다.
- 소리는 넣지 않았다(음원 미정).

## 다음에 고칠 만한 것

- 갤러리 장면은 하트 하나만 바뀌어 거의 정지 화면이다. 카드를 눌러 크게 보는 동작을 녹화하면 더 살아난다.
- 앱 화면 속 작은 글을 읽히게 하려면, 고르기 버튼이나 AI 대답처럼 중요한 곳을 살짝 확대(펀치인)하는 안을 검토한다.
